# Third-party license registry

A small Go command, driven by a small make include, that generates and
verifies a `NOTICE.txt` + `licenses/` third-party attribution registry for a
Go binary: it runs [`go-licenses`](https://github.com/google/go-licenses)
against your main package for every platform you release, unions the
results (so a platform-specific dependency like a Windows-only package still
gets attributed), rejects any dependency whose license isn't an acceptable
type unless it's on a hand-reviewed exception list (for a copyleft license
like MPL-2.0), and re-verifies that exception list against the union too, so
a stale or upstream-relicensed entry doesn't stay exempted silently.

This directory is meant to be copied into another repository wholesale and
used as-is — nothing in it is specific to the repo it started in.

## Adopting it in a new repo

1. Copy this whole `tools/licenses/` directory into the new repo (same
   relative path is simplest, but not required — see below). The tool
   parses YAML with `gopkg.in/yaml.v3`; run `go get gopkg.in/yaml.v3` in the
   adopting repo if it isn't already a dependency.
2. In the new repo's root `Makefile`, add:

   ```makefile
   LICENSES_PLATFORMS := linux_amd64 linux_arm64 darwin_amd64 darwin_arm64 windows_amd64
   LICENSES_ALLOWED_MPL :=
   include tools/licenses/licenses.mk
   ```

   `LICENSES_PLATFORMS` should match the `goos`/`goarch` combinations (minus
   any `ignore` entries) your release process actually builds. `licenses-check`
   hard-depends on `licenses-platform-guard`, which **requires** a goreleaser
   config and fails if `LICENSES_PLATFORMS` drifts from its `builds:` matrix.
   If yours lives somewhere other than the repo root's `.goreleaser.yml`, set
   `LICENSES_GORELEASER` to its path. If you don't use goreleaser at all,
   override or replace the `licenses-platform-guard` target yourself — you
   then own keeping `LICENSES_PLATFORMS` correct by hand, with nothing left
   to check it against.

   Use a hard `include`, not `-include`: a missing or misconfigured
   `licenses.mk` should break the build loudly, not silently turn
   `licenses-check` into a no-op.

   The `include` line finds the rest of this tool relative to its own file
   path, so `tools/licenses/licenses.mk` works unmodified regardless of
   which repo it's included from or where `make` is invoked. Copying the
   folder to a different path just means writing that path in the `include`
   line.
3. Add a `LICENSES_ALLOWED_MPL` entry (a space-separated list of Go module
   import paths) for every dependency you've reviewed and accepted despite
   go-licenses classifying its license as non-permissive — start empty if
   you have none yet.
4. Create `NOTICE.header` at the repo root: a hand-written header for
   `NOTICE.txt` (any attributions that don't come from `go.mod`, e.g. for
   code your build process generates from a third-party spec, plus a note
   that test/build-only dependencies aren't listed) ending in a line reading
   `Third-party Go modules:` — `generate` appends one block per dependency
   after it. `licenses/` and `NOTICE.txt` themselves are fixed conventions,
   not configurable — both land at the repo root.
5. Wire `make licenses-check` into CI alongside your other verification
   steps, and commit `NOTICE.txt` + `licenses/` (both generated by `make
   licenses`, never hand-edited) once they exist.

## Working files

**The go-licenses binary** is installed once per version under your user
cache directory (`os.UserCacheDir()`, e.g. `~/.cache` on Linux or
`~/Library/Caches` on macOS), at
`go-licenses-registry/go-licenses@<version>/go-licenses`. Re-running with
the same `--go-licenses-version`/`GO_LICENSES_VERSION` reuses it; a version
bump installs fresh into its own directory. If `os.UserCacheDir()` errors,
it falls back to the system temp directory with the same layout. This is
the tool's only working file outside the repo, so a checkout stays clean
without any ignore rules.

## Subcommands

Invoked as `go run ./tools/licenses <subcommand> [flags]` (the `licenses.mk`
targets below already do this with the right flags; you only need these
directly for debugging or for a repo shaped differently than the make
targets assume).

- **`generate`** — regenerates `NOTICE.txt` and the `licenses/` directory.
  For every platform, it unions go-licenses' `save`/`report` output and runs
  its license-type gate (permissive/notice/unencumbered pass; everything
  else must be on `--mpl`'s exception list or the run fails), then
  re-verifies that exception list against the merged result. Flags:
  `--go-licenses-version` (required — installs and caches the binary; see
  "Working files"), `--module` (this module's own import path, excluded
  from the registry; defaults to `go list -m`'s output, so it's usually left
  unset), `--package` (the main package to analyze, default `.`),
  `--platforms` (space-separated `GOOS_GOARCH` pairs), `--mpl`
  (space-separated reviewed exception module paths).
- **`check-platforms`** — verifies a declared platform list against a
  goreleaser config's build matrix. Flags: `--goreleaser` (default
  `.goreleaser.yml`), `--platforms`.

A repo with more than one main package (or one that isn't at the module
root) can point `generate` at the one that matters via `--package`; the
`licenses.mk` target keeps the default (`.`).

## Guard failure modes

`licenses-check` fails loudly rather than passing silently at any of these
steps, in the order they run:

1. **`licenses-platform-guard`** (`check-platforms`) — fails if
   `LICENSES_PLATFORMS` no longer matches the goreleaser build matrix, or if
   the config's YAML doesn't parse, declares no builds, or its builds yield
   an empty goos/goarch matrix.
2. **`generate`'s license-type gate**, run once per platform — fails if any
   dependency has a license type other than permissive/notice/unencumbered
   and isn't on the reviewed exception list, so a newly added dependency
   with an unacceptable or unclassifiable license fails the run on whichever
   platform pulls it in, and a registry is never written for it.
3. **`generate`'s MPL re-verification**, run once against the merged,
   all-platforms result — fails if an exception list entry no longer
   appears in the dependency graph at all (a stale exception — remove it),
   or if its license is no longer exactly what was reviewed (an upstream
   relicense — re-review it).
4. **Regenerate-and-diff** (the `licenses` target's output, then a
   `git status` check) — fails if regenerating `NOTICE.txt`/`licenses/`
   produces a diff, meaning a dependency changed without the registry being
   regenerated and committed alongside it.
